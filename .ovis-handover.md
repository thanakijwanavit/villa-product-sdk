    - **Delete after a retry:** after a 200 answer no listed code has a row left. When the SDK retries a lost
      answer, a code the first attempt deleted comes back in `missing`, so a clean-up check treats either list as
      gone.
    - **Rebuild race:** the hourly rebuild and a sync rebuild can overlap (the dump function has no concurrency
      limit). The "never replace a newer file" check and the write must therefore be one step: a conditional PUT
      (`If-Match` on the ETag it compared against, `If-None-Match: *` when there was no file) that compares again on
      412 or 409. Checked offline: moto 5.2.4 refuses both stale writes with 412 and keeps the newer file.
  - `9a91473` (committed 21:34, before the review was sent):
    - **Return values:** `querySingleProduct`, `queryList` and `allQuery` return the same types in both modes. The
      results of `updateWithS3` and `syncS3` differ by mode, so code that reads them checks `sdk.mode`. Q2's "change
      only the constructor" now says it is about `allQuery`.
    - **Retries:** timeouts are retried like connection errors. The presigned S3 GET and PUT retry on 500 and 503.
      `/ingest` is never retried. The fixture gains `retry.s3Statuses` and `retry.connectionErrorsAndTimeouts`.
    - **Frame typing:** in both modes `read_json` reads a column of digit strings as integers, or floats when rows
      lack the field, so a barcode loses its leading zero in the frame. The file, `querySingleProduct` and
      `queryList` keep exact values. Checked with pandas 2.3.3 and 3.1.0 (`uv run --offline --no-project --with
      pandas==<v>`).
